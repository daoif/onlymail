# 0007 — 正式 Release 更新提醒

## 决策

实例的更新提醒只认 `daoif/onlymail` 的正式 GitHub Release，不认普通 push，也不认没发 release 的 commit。

系统把“自动更新”和“更新提醒”拆开：

- 配了 GitHub 自动同步的实例，继续走 `Upstream Sync + Deploy Worker + Deploy Frontend`
- 没配自动同步的实例，只收到提醒，不自动更新代码

## 原因

当前部署路径有三类：

1. 自己维护仓库并自动部署
2. fork 上游并自动同步
3. 本地部署，或者 fork 了但没配自动同步

前两类已经有自动部署路径。真正缺的是第 3 类：实例还在跑，但管理员对新版本没有感知。

提醒只认正式 release，有两个好处：

1. 用户看到的是可以真正跟的版本，不是零散 commit
2. release note 可以和更新提醒对应起来，管理员知道自己在跟什么

## 落地方式

1. Worker 定时任务每 24 小时检查一次 `daoif/onlymail` 的最新正式 release
2. 检查结果写进 D1 `settings`
3. 登录后的管理面板根据 D1 状态显示顶部更新横幅
4. 设置页提供版本信息、手动检查按钮和更新入口

## 关闭策略

有新版本时，横幅支持两种关闭动作：

- `仅关闭本次更新通知`
- `永久关闭更新通知`

语义固定如下：

- 本次关闭：只对当前这个最新版本生效；如果后面又发布了更高版本，横幅重新出现
- 永久关闭：只关闭横幅，不影响设置页继续显示版本信息和手动检查入口
