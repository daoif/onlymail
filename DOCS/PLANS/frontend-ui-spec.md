# 前端 UI Spec

## 目标
- 管理面板整体采用白色主色调。
- 布局和视觉以清晰、克制、可连续使用为准，不做装饰型堆叠。
- 只使用 Tailwind CSS，不引入任何 UI 框架或组件库。

## 视觉基调
- 页面主背景使用白色或接近白色的浅色。
- 文字以深灰为主，不使用纯黑做大面积正文。
- 强调色只做少量状态提示、链接和主按钮，不把页面做成彩色面板。
- 优先用排版、对齐和留白建立层次，不靠阴影、描边和色块堆层次。

## 边框规则
- 边框只在需要表达结构分隔时使用，比如页面主区域和筛选栏、列表和详情区、表头和表体。
- 不要给每个卡片、每个列表项、每个按钮都单独套一层边框。
- 同一块区域里，如果已经靠背景、排版或间距分层，就不要再补一圈边框。
- 按钮默认优先用底色、文字色和 hover 态区分；只有次要按钮或危险按钮确实需要弱化时，才加轻边框。

## 间距规则
- 间距跟着上下文走，不做固定套路。
- 如果父容器已经有明显 `padding`，子组件外层不要再叠 `margin`。
- 同一层级的列表、表单、筛选条、工具栏，优先保持同一套纵向节奏，不要这一块松、那一块挤。
- 表格页和双栏页的间距要比登录页更紧，避免后台页面显得空。
- 先看组件处在什么区域里，再决定间距大小，不要把一套 `p-6 gap-6` 到处复制。

## 组件上下文要求
- 登录页可以更聚焦，允许更明显的留白，但不要做多层卡片包裹。
- 仪表盘数字区用排版和分组表达层次，不要做厚重卡片墙。
- 地址页、域名页、设置页优先表格或列表布局，不把每条记录做成独立卡片。
- 邮件页的列表区和详情区需要明确分区，但分区方式优先用布局和浅分隔，不用重边框堆满。
- 弹窗只在删除确认、API Key 轮换确认这类必要动作上使用，不额外加流程页。

## 技术约束
- 只允许使用 Tailwind CSS 写样式。
- 不使用 Naive UI、Element Plus、Ant Design Vue、Vuetify 等 UI 框架。
- 不引入现成的通用组件皮肤系统；需要的按钮、输入框、表格、弹窗，直接在项目里按场景写。
- 可以使用小型功能库处理非视觉问题，比如 `DOMPurify` 这种安全清洗工具，但它不参与视觉层。

## 页面级要求

### 登录页
- 白底。
- 居中单列布局。
- 只保留标题、输入框、按钮和错误提示。
- 不加品牌插画、大图标墙和多余介绍文案。

### 仪表盘
- 以简要数字和最近状态为主。
- 统计块不做厚重卡片，优先轻分组或简单栅格。
- 不加图表，除非后面业务真的需要。

### 地址页
- 主体是表格。
- 筛选区和表格区是同一条操作链，不要拆成多个盒子。
- 行内操作保持短路径，直接提供“查看邮件”“删除”。

### 邮件页
- 默认双栏或上下分区布局。
- 左侧邮件列表密度可以高一些，方便快速浏览。
- 右侧详情阅读区保持干净，正文区域不要再套多层边框。

### 域名页
- 以列表和操作条为主。
- 根域名初始化状态要放在用户一眼能看到的位置。
- 新增子域名的输入和提交动作放在同一块区域，不拆流程。

### 设置页
- API Key 预览、复制、轮换是主内容。
- 危险操作和普通信息要视觉分层，但不要靠大面积红框吓人。

## 实现检查清单
- 页面是不是白色主色调。
- 当前区域的边框是不是只出现在真正需要分隔的地方。
- 当前区域的间距是不是结合上下文，而不是整站复制固定数值。
- 有没有引入 UI 框架或组件库。
- 一个页面里，是否主要靠排版、布局和少量分隔建立层次。
