# 项目范围

## 当前状态
- `cfte` 参考项目已经研究完。
- 任务方案已经进入可实施状态，不再处于“等研究完成后再细化”的阶段。
- 后续新增内容以 `backend-infra.md`、`frontend-sdk.md`、`engineering-sdk.md` 为准。

## 核心定位
- 这是一个专为注册机打造的个人邮箱系统。
- 服务端保持精简，复杂轮询和批量行为放到 SDK。
- 同时提供自动化 API 和人用的 Web 管理面板。

## 确认保留的能力
- 临时邮箱和永久邮箱，两者只用 `ttl_hours` 区分。
- 子域名自动化管理。
- 项目隔离和地址占用状态返回。
- 邮件原文保留。
- Web 管理面板。
- Node.js 和 Python SDK。

## 这次补进来的关键调整
- API Key 改成可轮换的持久化配置，不再写成只靠环境变量读取。
- 邮件 HTML 和文本内容在收件时解析并入库，管理面板不在浏览器里解析 MIME。
- 根域名初始化单独成一步，子域名创建依赖这个前置状态。

## 不做的事
- 不做多用户。
- 不做发件。
- 不做 Webhook。
- 不做服务端验证码提取。
- 不做服务端批量接口。

## 架构分层
- SDK：地址生成策略、轮询、重试、超时、验证码或链接提取、批量并发。
- Worker API：地址、邮件、域名、设置、统计。
- Web 管理面板：登录、仪表盘、地址、邮件、域名、设置。
- Cloudflare 基础设施：Email Routing、DNS API、D1、Pages。

## 交付判断标准
- Worker 本地能起。
- 前端本地能起。
- 地址能创建、邮件能接收、域名能初始化和创建子域名。
- 管理面板能完整走通登录、查询、设置和域名管理。
- SDK 能在很短的代码里完成“创建地址 -> 等邮件 -> 取正文”。
