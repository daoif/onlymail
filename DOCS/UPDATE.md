# 更新路径

这份文档只说一件事：OnlyMail 部署好以后，怎么跟上新版本。

系统现在把“更新”拆成两层：

1. 代码自动部署
2. 新版本提醒

两层不是一回事。

---

## 1. 你自己维护的仓库

如果实例就是从你自己的仓库部署的，后面你改代码再 push，GitHub Actions 会直接自动部署：

- `CI`
- `Deploy Worker`
- `Deploy Frontend`

这条线不需要额外配置更新提醒，因为你自己就是代码维护者。

---

## 2. fork 上游仓库，并且想自动跟上更新

这是推荐的自动更新路径。

先确认两件事：

1. 你的仓库已经配好 GitHub Actions 和 Cloudflare secrets
2. 默认分支尽量保持干净，不要长期堆自己的分叉提交

然后在仓库变量里设置：

```text
UPSTREAM_REPOSITORY=daoif/onlymail
```

再启用：

- `Upstream Sync`

它会做这些事：

1. 每 12 小时检查一次上游默认分支
2. 如果你的默认分支还能 fast-forward，就把上游代码同步下来
3. 同步成功后，再显式触发：
   - `CI`
   - `Deploy Worker`
   - `Deploy Frontend`

这条线只接受 fast-forward。

也就是：

- 你的默认分支和上游还在同一条线上，它能自动更新
- 你的默认分支已经有自己的分叉提交，它会停下来，等你手动处理

---

## 3. 没配自动同步，或者是本地部署

这类实例不会自动更新代码。

系统会改成提醒你：

1. Worker 每 24 小时检查一次 `daoif/onlymail` 的最新正式 GitHub Release
2. 只认正式 release tag，例如 `v0.1.0`、`v0.2.0`
3. 不认普通 push，也不认没发 release 的 commit
4. 管理面板登录后会显示更新横幅
5. 设置页可以手动点“立即检查更新”

所以这条线的行为是：

- **会提醒**
- **不会自动更新**

---

## 4. 更新横幅怎么工作

只要实例版本落后于最新正式 release，登录后的管理面板顶部就会出现横幅。

横幅里有这几个动作：

- `查看如何更新`
- `查看项目仓库`
- `仅关闭本次更新通知`
- `永久关闭更新通知`

这两个关闭动作的语义固定如下。

### 仅关闭本次更新通知

只对当前这个最新版本生效。

例如：

- 当前最新版本是 `0.2.0`
- 你点了“仅关闭本次更新通知”

那么：

- `0.2.0` 这一轮不会再提醒
- 等 `0.3.0` 发布后，横幅会重新出现

### 永久关闭更新通知

只关闭顶部横幅。

设置页里的这些信息仍然保留：

- 当前版本
- 最新版本
- 上次检查时间
- 手动检查按钮
- 更新文档和仓库入口

---

## 5. 设置页能看到什么

设置页的“版本更新”区块会显示：

- 当前版本
- 最新版本
- 上次检查时间
- 当前是否有更新
- 手动检查按钮
- 重新启用更新通知按钮（如果你之前永久关闭过）

所以就算你不想要横幅，版本信息也不会完全消失。

---

## 6. 手动更新怎么做

### 本地部署

先把新版本代码拉下来，然后按改动范围跑：

```bash
pnpm install
pnpm deploy:worker
pnpm deploy:frontend
```

如果 release note 里写了需要重建平台内部状态，再跑：

```bash
pnpm run rebuild
```

### GitHub-only / 混合部署

如果你的仓库没配 `Upstream Sync`，就手动把上游新版本合进来，然后 push 到默认分支。后面的 `CI`、`Deploy Worker`、`Deploy Frontend` 会自动跑。

---

## 7. 当前限制

这套更新提醒不会做这些事：

- 不会自动下载 release
- 不会自动改你的代码仓库
- 不会自动替你处理破坏性迁移
- 不会在没登录后台时主动弹提醒

它只负责一件事：

**告诉管理员：有新的正式版本可以跟了。**
